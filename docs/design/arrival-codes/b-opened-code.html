Arriving near a booking: the opened code

What a tap on the notification or the Upcoming card opens. Parking reuses the existing QR code dialog; rental pickup and hotel show the confirmation number. Phone width only, dark only, vector only. Every place, name, code and time is made up; the QR pattern is random and encodes nothing.

B1

Parking: the QR code

The notification and the card open the existing Show QR code dialog (GateCode.svelte), unchanged: the picture on a white square, the lot and its times, and the brightness line. Decided 2026-11-18: the iPhone app keeps the picture with the saved trips, so this is what you see online and with no connection. Closing it leaves you on the trip page of that booking.

B2

Parking: no picture on the phone yet

The rare case left: no connection, and the saved copy has no picture for this booking (the code arrived in a reminder after the last save, or no code was chosen yet). The dialog keeps its failure line and also shows the booking’s confirmation number, which is always saved, so the attendant has something. In a browser the dialog is unchanged.

B3

Rental pickup and hotel: the confirmation number

Waypoint holds no pickup code, locker code, room key or check-in QR for these kinds (see the README), so what comes up is the confirmation number (hotels included, decided 2026-11-18), large and copyable, with what the counter or front desk asks for. A new dialog, built from the same parts as the QR code dialog. Nothing in it is new data.
