Reconstructed, not the original canvas

#876 asked for the owner's approved mockups to be put here, but they live only on the owner's private design canvas, which the agents working on this repository cannot open. This file is a reconstruction: drawn from the decisions written in #876 and #875, the tokens of #880, and the components as built in #899, #902, #904, #905 and #906, so it shows what the app now shows. Where the build departs from a written decision it is drawn as built and listed in the README. Every name, place, flight, seat, code, price and date is made up.

What this shows

  1. Page, card, text greys and the hairline.
  2. Blue, green and amber, and what each may mean.
  3. The booking-type icon colours.
  4. The three colour options, with option C (blue and green) marked as chosen; A and B are not described in writing and are not drawn.

The colour rules

#876 decision 3 and #875 decision 5, with the token each maps to in the build.

Blue #3d8ef7

  • Live, now, or the one primary action.
  • The plane marker and in-air progress, the countdown, “Boarding”, “Show code”, the Next marker in the day list.
  • Token --primary.

Green #4cc38a

  • Confirmed, on time, or good news.
  • “on time”, “Confirmed”, “7 min early”.
  • Token --success.

Amber #eba43b

  • Something changed or needs attention.
  • A delayed time, the “Delayed” pill, the dot on the review line, “Changed”.
  • Token --signal; the light ink #ffd58a (--signal-ink) for amber text.

Nothing else is coloured, apart from the kind icons below.

The three colour options

The owner chose between three colour options on the canvas and picked option C, blue and green (#875: “option C of the colour options board”). The written record says nothing more about options A and B, so they are not drawn: inventing them would misstate what the owner saw. Option C is shown with one card that uses all three colours.
