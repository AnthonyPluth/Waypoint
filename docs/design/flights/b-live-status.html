Live flight status: the in-flight view

Mockups for the live flight status view, a full page opened from a flight's card or row. Drawn with Waypoint's own tokens (frontend/src/app.css), dark only. Use the toggle to see phone (390 px) or desktop (1280 px; the 960 px content column). Every flight, name and airport here is made up.

What this shows

  1. A big route (the card's route, larger) with the plane on its arc, the headline Landing in 38 minutes and a progress bar.
  2. A departed / in the air / lands timeline with scheduled and actual wall-clock times, each with the zone shown where it matters.
  3. Arrival facts in big type (Terminal, Gate, Belt) marked by source, seats per traveller from the booking, and Refresh with when the data was last updated.
  4. Drawn for a flight in the air; the other states reuse the card's pill and sentence (a) with the timeline steps that apply.

Live status, in the air

The view opens from any flight card or row. The headline changes with the state (Departs in 2 hours 10 minutes, Boarding now at gate B14, Landed 3 minutes early); this page draws the in-air case, which has the most to show.

Accessible names

  • Back is a link named Back to Four Corners loop (the trip's name). The icon-only Refresh on phone is a button named Refresh flight status; on desktop it shows the word Refresh.
  • The headline (Landing in 38 minutes) is the page's h1 and a polite live region, so a refresh that changes it is announced once.
  • The progress bar is a progressbar named Flight progress with its value; the timeline is a list named Flight timeline, one item per step.
  • Arrival facts are a dl with the same source dots and Not known yet as the card; seats are a list named Seats by traveller.

Tokens and components

  • Same card, pill, mark tile and source dots as a. The progress bar is --surface-3 with a --status-info-ink fill; timeline dots: done --status-ok-ink, now --status-info-ink with a soft halo, next a hollow ring.
  • The headline is text-2xl semibold on phone, 28 px on desktop. Times in Geist Mono. Refresh is the existing secondary button (btn sm on desktop, a 44 px icon button on phone).
  • Desktop: two columns (1.4fr and 1fr) in the 960 px content column.

Replaces

  • Nothing: this is a new view, opened from the card (a), the booking row (c) and the Home card (c). It takes over the Refresh button and the gate lines now in FlightStatus.svelte.
  • Refresh asks the status service only when the app already would (REFRESH_AFTER, see docs/design/flight-gates.md); a failed refresh keeps the old data and says when it was last updated, never Updated just now.
