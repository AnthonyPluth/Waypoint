# User feature map

Generated by `tools/user_feature_map.py` (`make user-feature-map`); do not edit. The gotchas come from [feature-gotchas.md](feature-gotchas.md), which is hand-edited. `make fleet-checks` fails when this file is out of date.

What a person can do in the web app, by page: what is there, how to reach it, how to drive it with `tools/control` (or `make verify`), and what usually breaks. It is not `docs/feature-map.json` (and its docs page, `make feature-map`), which goes by API route to find the code behind a feature: that map starts from a route and ends at a handler, a test and a docs page; this one starts from what a user sees, from the pages and flows `make verify` runs, and ends at the commands that drive it. All of it is demo data; `tools/control start` first, and `flow <name>` runs a flow's steps (after `reset` for the data `make verify` starts it from).

## Upcoming (`upcoming`)

- **What exists:** No docs page of its own.
- **Reach it:** desktop: the sidebar's Upcoming; phone: the tab bar; URL `#upcoming`; control `tools/control goto upcoming`.
- **Drive it:** `tools/control goto upcoming`, `tools/control snapshot --text`, then `click`/`type`/`press`; `tools/control viewport phone|desktop`; batch check `make verify PAGES="upcoming"`.
- **What usually breaks:**
  - A session that hasn't run `tools/control offline` shows an "Offline access" panel saying the device can't make a passkey; make verify's images show the page after offline access is set up.
  - The first card is the next thing under way on the frozen day (2026-06-15): in the demo it is a London hotel check-in two days out. Nothing here moves with the real date.

## design (`design`)

- **What exists:** No docs page of its own.

## oauth-approve (`oauth-approve`)

- **What exists:** No docs page of its own.
- **Reach it:** not a route of the app: an assistant's connection request, a page the server serves at /oauth/authorize; make verify opens it with a request it seeds first, so `goto` can't.
- **What usually breaks:**
  - Not a route of the app: it is the page an assistant's connection request lands on. make verify registers made-up assistants and opens it; `tools/control` has no way to, so check it with `make verify PAGES="oauth-approve"`.
